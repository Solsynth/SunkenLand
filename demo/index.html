OAuth login (sk-login)

Solarpass sign-in is a real OpenID Connect client flow: discovery → id.solian.app/auth/authorize (popup, authorization code + PKCE) → /stargate/auth/open/token. This demo stubs the provider, so clicking the button runs that exact code path against the stubbed endpoints and logs the authorize URL above.

Reply composer (sk-reply-composer)

Signed out it shows "Sign in with Solarpass"; signed in it posts to POST /sphere/posts?pub=<publisher> with replied_post_id=post_1. The publisher chip switches between the account's publishers (this demo stubs two), and the list above re-fetches after posting.

Reactions (sk-reaction-list)

Counts come from GET /sphere/posts/post_1; the chip you own is highlighted once you are signed in (the demo stubs you as having reacted with a heart). Clicking a chip or a reaction in the picker is optimistic — it calls POST/DELETE /sphere/posts/post_1/reactions… and rolls back if the request fails. Signed out, clicking starts the Solarpass popup. The demo stubs six reactions so the +1 toggle shows, and renders the stickers that ship with the package (dist/stickers/, via configure({ stickerUrl })).

Username (sk-username)

sk-username renders a name the way FloatLand's AccountName does: the profile's custom colour, gated by the Stellar tier (primary → named palette colours, nova → any plain colour, supernova → gradients), with the membership, verification, and bot marks beside it. The first two read the account through GET /stargate/accounts/{id}; the third has no custom colour, so it falls back to its tier's colour. Attributes work without an account too: <sk-username name="Fan" color="purple" tier="solian.stellar.primary" verified></sk-username>.

Post (sk-post)

sk-post renders one whole post the way FloatLand's PostCard does: the author header (avatar and the colourful name), the Markdown body, attachments through the shared media grid, tags, metadata, the reaction summary, and the stats footer. Reads are public through GET /sphere/posts/{id}. App-only actions — the overflow menu, boosting, the composer, and reporting — are out of scope: pair it with sk-reaction-list / sk-reply-composer, or listen for post-click.

Media (sk-media / sk-media-collection)

sk-media renders one drive file like FloatLand's AttachmentItem (video with a play overlay, image through unlazy, <audio controls>, or a file card); sk-media-collection renders a list like AttachmentGrid — one file fills a box at its aspect ratio, several become a snapping list with a n/total counter and scroll arrows. Ids are resolved through GET /drive/files/{id}/info for the name, MIME type, dimensions, and blurhash; a file whose wire object has url: null then loads from …/drive/files/{id}. Clicking one dispatches media-click (logged below) and opens the file in a new tab unless the event is canceled. Reply attachments render through the same grid — see the reply list above.

Host-provided token (no login button)

A host that already holds a credential can skip the login button: clicking this configures a ready-made access token, and the widgets switch to the signed-in state on their own (resolved through the API). The demo stubs it as at_configured_demo.

Customization (tokens + ::part)

This one overrides --sk-btn-* tokens and styles ::part(button) from the page CSS (2px dashed border, square-ish radius, custom label).

apiFetch (authenticated SDK calls)

SunkenLand.apiFetch(path, options) attaches the session token, refreshes once on 401, snake_cases bodies, and can validate with the package's zod schemas. Needs a signed-in session — use the simulate button above first.
